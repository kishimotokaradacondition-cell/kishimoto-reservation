# サルコペニア簡易評価アプリ（院内用）

来院者の **サルコペニア（加齢による筋肉量・筋力の低下）** を、AWGS 2019 の基準で
ふるい分け（スクリーニング）する院内ツールです。
名前・性別・SARC-F（5問の選択式質問）・握力・歩行速度・椅子立ち上がり・InBody の筋肉量を入力し、
InBody の結果用紙の写真を添えて記録します。

> **位置づけ**: 結果は「〜の可能性」「〜の疑い」というスクリーニング判定です。
> 医師の診断ではないので、画面・説明では「診断」という言葉を使っていません。

## 予約システムとの関係

- `../app.py`（予約システム）とは **完全に別のアプリ** です。コードもデータベース（`sarcopenia.db`）も共有しません。
- 理由: 以前 InBody 連動の食事管理アプリを予約システムに組み込み、後で切り離した経緯（PR #16 → #17）があるため、
  最初から分けておき、将来このフォルダごと別リポジトリに移せる形にしています。
- 患者の健康情報を扱うので、公開中の予約サイトと同じプロセスに載せないほうが安全です。

## 院内の Mac（MacBook Air M3）で使う ← 標準の運用

データは Mac の **ホーム直下の `サルコペニア評価` フォルダ**（Finder で「移動」→「ホーム」）に保存します。
「書類」「デスクトップ」「ダウンロード」は macOS の保護対象で、ログイン時に裏で自動起動するプログラムからは
読み書きできないため、保護対象外のホーム直下を使います。
院の Mac→NAS 自動バックアップ（`scripts/backup/pc-to-nas/mac`）はこのフォルダも対象に含めてあるので、
評価データと画像は NAS → クラウドへ二重化されます。

```
~/サルコペニア評価/
├── sarcopenia.db          本体（入力内容・判定結果・InBody 画像がすべて入っている）
└── backups/
    └── sarcopenia-YYYY-MM-DD.db   1日1回自動で作る複製（30日分）
```

アプリ本体は同じ理由で `~/Library/Application Support/kishimoto-sarcopenia` にコピーして動かします
（ダウンロードしたフォルダは「書類」などに置いたままで構いません）。

### 初回セットアップ（1回だけ）

1. このリポジトリを Mac にダウンロードして展開（GitHub の「Code」→「Download ZIP」）
2. ターミナルを開き（Launchpad で「ターミナル」を検索）、次を入力して Enter（`cd ` の後に `sarcopenia/mac` フォルダをドラッグ＆ドロップすると場所が入ります）
   ```
   cd ＜展開したフォルダ＞/sarcopenia/mac
   ```
3. 次を入力して Enter
   ```
   bash setup.command
   ```
   - Python が無いと言われたら、画面の案内どおり `xcode-select --install` を実行してからやり直す
   - ※ `.command` をダブルクリックすると macOS の安全機能で止められるため、ターミナルから実行します
4. 自動でブラウザが開き http://localhost:5070 が表示されたら完了。ブックマークしておく

セットアップ後は **Mac にログインするたびに自動で起動** します。ブラウザで http://localhost:5070 を開くだけです。
開かないときは、ターミナルで同じフォルダに移動して `bash open.command`（起動し直してから開きます）。

同じ Wi-Fi 内の iPhone/iPad からは `http://＜MacのIPアドレス＞:5070` で開けます
（Mac の IP は システム設定 → Wi-Fi → 詳細 で確認）。この場合は後述の `SARCOPENIA_PASSWORD` の設定を推奨。

| ファイル | 役割 |
|---|---|
| `mac/setup.command` | 本体のコピー ＋ 実行環境の作成 ＋ 自動起動の登録 ＋ 起動確認。アプリを更新したときも再実行すれば反映 |
| `mac/open.command` | アプリを開く。止まっていれば起動し直す |
| `mac/uninstall.command` | 自動起動を解除（データは消さない） |

### 元に戻したいとき（誤って削除した等）

アプリを止めて（`bash uninstall.command`）、`backups/` の中の戻したい日付のファイルを
`sarcopenia.db` という名前にして上書きし、`bash setup.command` を再実行します。

## その他の環境で起動する場合

```bash
cd sarcopenia
pip install -r requirements.txt
python app.py
```

ブラウザで http://localhost:5070 を開きます。Mac 以外ではデータは `sarcopenia/sarcopenia.db` に保存されます。

## インターネット上に置く場合（Render など）

予約システムとは **別サービス** として作成します。

| 設定項目 | 値 |
|---|---|
| Root Directory | `sarcopenia` |
| Build Command | `pip install -r requirements.txt` |
| Start Command | `gunicorn app:app --bind 0.0.0.0:$PORT --workers 2 --timeout 120`（Procfile と同じ） |

環境変数（公開する場合は上2つを **必ず** 設定）:

| 環境変数 | 役割 |
|---|---|
| `SARCOPENIA_PASSWORD` | 設定するとログイン画面が付きます。未設定だと誰でも開けるので公開時は必須 |
| `SECRET_KEY` | ログイン状態を保持する鍵。長いランダム文字列にする |
| `SARCOPENIA_DB_PATH` | SQLite の保存先。Mac の既定は `~/サルコペニア評価/sarcopenia.db`。サーバーに置く場合は永続ディスク上のパスを指定する |
| `PORT` | 待ち受けポート（Render は自動で入る） |

> **注意**: 画像はデータベース（SQLite）の中に保存しています。DB ファイル1つをバックアップすれば
> 画像も含めて丸ごと残ります。逆に DB が消えると画像も消えます。

## 判定の根拠（AWGS 2019）

出典: Chen LK, et al. *Asian Working Group for Sarcopenia: 2019 Consensus Update on Sarcopenia
Diagnosis and Treatment.* J Am Med Dir Assoc. 2020;21(3):300-307.

| 項目 | 男性 | 女性 | 意味 |
|---|---|---|---|
| 下腿周囲長 | 34cm 未満 | 33cm 未満 | スクリーニング陽性 |
| SARC-F 合計 | 4点以上 | 4点以上 | スクリーニング陽性 |
| SARC-CalF 合計 | 11点以上 | 11点以上 | SARC-F ＋（下腿周囲長が基準未満なら +10点） |
| 握力 | 28kg 未満 | 18kg 未満 | 筋力低下 |
| 6m 歩行速度 | 1.0 m/秒 未満 | 同 | 身体機能低下 |
| 5回椅子立ち上がり | 12秒以上 | 同 | 身体機能低下 |
| SMI（BIA = InBody） | 7.0 kg/m² 未満 | 5.7 kg/m² 未満 | 筋肉量低下 |

SMI（骨格筋指数）＝ **四肢骨格筋量 ASM（右腕＋左腕＋右脚＋左脚 の筋肉量 kg）÷ 身長(m)²**

判定フロー:

```
筋肉量低下 ＋ 筋力低下 ＋ 身体機能低下   → 重症サルコペニアの可能性
筋肉量低下 ＋（筋力低下 または 身体機能低下）→ サルコペニアの可能性
筋肉量 未測定 ＋（筋力低下 または 身体機能低下）→ サルコペニアの疑い（InBody で確定）
筋肉量 基準内 ＋（筋力低下 または 身体機能低下）→ 筋力・身体機能の低下あり（運動介入の対象）
筋肉量低下のみ                          → 筋肉量の低下のみ（予防的介入・半年後に再評価）
スクリーニングのみ陽性                  → 要・測定（握力・歩行・InBody）
すべて基準内                            → 基準上は該当なし
```

## InBody の数値はどこを見るか

結果用紙の **「部位別筋肉量」（Segmental Lean Analysis）** にある右腕・左腕・右脚・左脚の kg を転記します
（体幹は含めない）。用紙に **SMI** が印字されている機種なら、その値を「SMI を直接入力」に入れれば優先されます。
「骨格筋量（SMM）」は全身の値で ASM とは別物なので、そのまま SMI の計算には使わないでください。

## ファイル構成と「どこを変えると何が変わるか」

```
sarcopenia/
├── app.py                 サーバー本体（画面を返す・保存する・一覧を返す）
├── criteria.py            判定ロジック。基準値 CUTOFFS と SARC-F の質問文はここ
├── templates/index.html   入力画面と結果表示の骨組み
├── templates/login.html   ログイン画面（SARCOPENIA_PASSWORD 設定時のみ使われる）
├── static/js/sarcopenia.js 入力中の自動計算・送信・結果と履歴の描画
├── static/css/sarcopenia.css 見た目（配色は予約システムと同じ）
├── mac/                   Mac 用のセットアップ・起動・解除スクリプト（ダブルクリックで実行）
├── tests/                 自動テスト（判定ロジック 23件、API 14件）
└── requirements.txt / Procfile
```

| やりたいこと | 触るファイル |
|---|---|
| 基準値を変える（例: 握力の cutoff） | `criteria.py` の `CUTOFFS` |
| SARC-F の質問文・選択肢の言い方を変える | `criteria.py` の `SARCF_ITEMS` / `SARCF_CHOICES` |
| 判定後の「次の一手」の文章を変える | `criteria.py` の `LEVELS` |
| 入力項目を増やす | `templates/index.html` に欄を追加 → `app.py` の `NUMERIC_FIELDS` と DB 列に追加 → 必要なら `criteria.py` |
| 色・レイアウト | `static/css/sarcopenia.css` |

## リスク・注意点

- **個人情報**: 氏名＋健康情報です。公開サーバーに置くなら `SARCOPENIA_PASSWORD` と `SECRET_KEY` の設定、HTTPS は必須。
- **データ消失**: Mac 運用ではホーム直下に保存し、日次複製 ＋ NAS バックアップで三重に守ります。サーバーに置く場合は無料プランのディスクが再起動で消えるため、永続ディスクが必要です。
- **Mac のスリープ**: 蓋を閉じるとアプリも止まります（開けば自動で再開）。iPhone から使う場合は Mac を起動したままにしてください。
- **基準値の対象年齢**: AWGS 2019 は主に 65 歳以上向け。65 歳未満では参考値として扱う旨を画面にも表示しています。
- **HEIC 画像**: iPhone から選ぶと自動で JPEG に変換されますが、パソコンで HEIC ファイルを直接選ぶと保存はできても表示できないことがあります。その場合は JPEG で保存し直してください。
- **名前が主キー**: 「前回比」は名前が完全一致した記録を探します。姓名の間の空白など、入力のゆれは候補表示（datalist）で防いでいますが、運用ルール（例: 全角スペース1つ）を決めてください。
