# 電子帳簿保存法（電子取引データ保存）対応 セットアップ手順

メールやWeb経由で受け取った請求書・領収書を、**電子のまま自動でGoogleドライブに保存し、
日付・金額・取引先で検索できる状態にする**仕組みです。

## なぜ必要か

2024年1月から、**すべての法人・個人事業主**を対象に、
メールやWebでやり取りした請求書・領収書などの電子データは
**紙に印刷して保存するだけでは不可**となり、電子データのまま保存する義務があります。

保存にあたっては、次の2つを満たす必要があります。

| 要件 | この仕組みでの満たし方 |
|---|---|
| **検索できること**（日付・金額・取引先） | 索引簿スプレッドシートに自動で1行ずつ記録。ファイル名も `20260801_Google_1234円.pdf` の形にそろえる |
| **改ざんできないこと**（真実性の確保） | 「訂正及び削除の防止に関する事務処理規程」を備え付ける（`docs/dencho-jimu-shori-kitei.md`）。あわせてGoogleドライブの版履歴も証跡として残る |

> **補足**: 検索要件は、基準期間（2課税年度前）の売上高が5,000万円以下の事業者であれば、
> 税務調査の際にデータのダウンロードの求めに応じられる場合は不要とされています。
> ただし索引簿があれば確実なので、この仕組みでは満たす形にしています。

## 全体像

```
届いた請求書メール（Google Workspace / Anthropic / Railway など）
   ↓ 毎朝6時に自動チェック
Google Apps Script（gas/dencho-invoice-archive.gs）
   ↓ 添付PDFを取り出す（添付がない場合はメール本文をPDF化）
Googleドライブ
   マイドライブ/電子帳簿保存（電子取引データ）/
     ├ 索引簿（電子取引データ）   ← 日付・金額・取引先で検索する一覧表
     ├ 受領/2024, 2025, 2026/    ← 受け取った請求書・領収書
     └ 発行/2024, 2025, 2026/    ← 自分が送った請求書の控え
   ↓
索引簿に1行追記 ＋ Gmailに「電帳法/保存済み」ラベルを付与
   ↓
結果をメールで通知（金額を自動で読めなかったものは「要確認」として報告）
```

**受け取った分だけでなく、自分が発行して送った請求書の控えも保存義務の対象です。**
この仕組みは送信メール（`in:sent`）も対象にしています。

## 現状の棚卸し結果（2026年8月時点）

導入前に、Gmailとドライブの中身を確認した結果です。

### 受領している電子請求書・領収書（自動保存の対象）

| 取引先 | 差出人 | 形式 | 頻度 |
|---|---|---|---|
| Google（Google Workspace） | `payments-noreply@google.com` | メールに**PDF添付**あり | 毎月1日ごろ |
| Google（Google Cloud） | `payments-noreply@google.com` | メール本文型（少額・¥24など） | 都度 |
| Anthropic, PBC | `invoice+statements@mail.anthropic.com` | 本文＋Web明細リンク | 月1回程度 |
| Railway Corporation | `invoice+statements+acct_…@stripe.com` | 本文＋Web明細リンク | 月1回程度 |

過去分は2025年8月〜2026年8月にかけて十数件を確認しました。`backfillAll()` で2024年1月までさかのぼって取り込みます。

### 発行している請求書（控えの保存対象）

ドライブの「やわらぎ > 請求書（きしもとマネジメントオフィス分）」に保存済みでした。

| ファイル | 備考 |
|---|---|
| やわらぎ様　請求書_8月度.pdf | 2026年8月分 |
| やわらぎ様　請求書　202607.pdf | 2026年7月分 |
| やわらぎ領収書発行20260729.pdf | 領収書 |
| 請求書_株式会社やわらぎ様_デザイン版（スプレッドシート） | 元データ。PDFではないため取り込み対象外 |

`importDriveFolders()` を実行すると、この中のPDFを「発行/2026」へコピーして索引簿に載せます。

### 対象外としたもの

- 予約システムの入金通知（`noreply@kishimotocondition.com`）— 自社システムの通知であり、取引先から受け取った書類ではないため
- Claudeの定期実行レポート（`no-reply-claude@mail.anthropic.com`）
- Google Workspaceの管理者向けお知らせ（`workspace-noreply@google.com`）

これらは `gas/dencho-invoice-archive.gs` の `EXCLUDE_SENDERS` で除外しています。

## セットアップ手順（所要時間 約15分）

### ステップ1: スクリプトを貼り付ける

1. **kishimoto.karada.condition@gmail.com でログインした状態で** https://script.google.com を開く
2. 「新しいプロジェクト」をクリック
3. 左上の「無題のプロジェクト」をクリックし、名前を **「電帳法 請求書アーカイブ」** に変更
4. エディタに最初から入っているコード（`function myFunction() {...}`）を全部消す
5. このリポジトリの **`gas/dencho-invoice-archive.gs`** の中身を全部コピーして貼り付ける
6. 保存アイコン（💾）をクリック

### ステップ2: フォルダと索引簿を作る

1. 上部の関数選択プルダウンで **`setup`** を選ぶ
2. 「実行」をクリック
3. 初回は「承認が必要です」と出るので、
   「権限を確認」→ アカウントを選択 → 「詳細」→「（安全ではないページ）に移動」→「許可」
   （自分のGmailとドライブを自分で操作するスクリプトなので問題ありません）
4. 下部の実行ログに、作られたフォルダと索引簿のURLが表示されます

この時点で、マイドライブに「電子帳簿保存（電子取引データ）」フォルダができています。

### ステップ3: まず「お試し実行」で中身を確認する（推奨）

1. 関数選択プルダウンで **`dryRunAll`** を選んで「実行」
2. 実行ログに「何が保存されるか」の一覧だけが出ます（**保存はされません**）
3. 取引と関係ないメールが混ざっていないか確認します
   - 混ざっていた場合は、`EXCLUDE_SENDERS` にその差出人を追加してから次へ

### ステップ4: 過去分を取り込む

1. 関数選択プルダウンで **`backfillAll`** を選んで「実行」
2. 2024年1月以降の請求書メールをさかのぼって保存します（数分かかることがあります）
3. 続けて **`importDriveFolders`** を選んで「実行」
   → 既存の「請求書（きしもとマネジメントオフィス分）」フォルダのPDFを発行控えとして取り込みます

### ステップ5: 毎日の自動保存をONにする

1. 関数選択プルダウンで **`installTrigger`** を選んで「実行」
2. これで毎朝6時台に `dailyArchive` が自動で走ります

以降、請求書メールが届いた翌朝には自動で保存され、結果がメールで届きます。

## 日々の運用

### 通知メールを見る

保存があった日は「【電帳法】日次の自動保存：◯件を保存しました」というメールが届きます。
金額を自動で読み取れなかったものは、メール末尾に「◯件は金額などを自動で読み取れませんでした」と出ます。

### 「要確認」を埋める

索引簿の **P列「要確認」** に `要確認` と入っている行は、次のどれかです。

- 金額を本文から読み取れなかった（Web明細リンク型の請求書に多い）
- メール本文をPDF化して保存した（正式なPDFがWeb側にある場合）
- 既存フォルダから取り込んだPDF（PDFの中身までは読んでいないため金額が空）

**月に1回、この行だけフィルタして金額・取引先を手で埋めてください。**
Web明細型の場合は、明細ページからPDFをダウンロードし、
保存先フォルダの該当ファイルと差し替える（同じファイル名にする）のが確実です。

### 日付・金額・取引先で検索する

索引簿スプレッドシートを開き、1行目を選択して **「データ」→「フィルタを作成」** を1回だけ設定しておきます。

- **取引先で探す**: C列のフィルタで取引先名を選ぶ
- **日付の範囲で探す**: B列のフィルタ →「条件でフィルタ」→「日付が次より後」
- **金額の範囲で探す**: D列のフィルタ →「条件でフィルタ」→「次より大きい」
- **組み合わせ**: 上記を同時に指定すればそのまま絞り込めます

税務調査でデータの提出を求められたら、
索引簿を「ファイル」→「ダウンロード」→ CSV または Excel で出力し、
該当フォルダのPDFとあわせて提出します。

### 新しい取引先が増えたとき

`gas/dencho-invoice-archive.gs` の `VENDOR_RULES` に1行足すだけで、
その取引先の名前で正しく保存されるようになります。

```js
{ fromContains: 'billing@example.com', vendor: '株式会社サンプル', docType: '請求書' },
```

ルールに書かなくても、PDF添付＋「請求書」などのキーワードがあれば自動で保存されます
（取引先名は差出人の表示名から推測するため、後で索引簿を直す前提になります）。

## 設定を変えたいとき

`gas/dencho-invoice-archive.gs` の先頭 `CONFIG` を編集して保存し直します。

| 項目 | 意味 |
|---|---|
| `ROOT_FOLDER_NAME` | 保存先フォルダの名前 |
| `BACKFILL_SINCE` | `backfillAll()` でさかのぼる開始日（既定: 2024/01/01） |
| `DAILY_LOOKBACK_DAYS` | 毎日の実行時にさかのぼって確認する日数（既定: 10日） |
| `NOTIFY_EMAIL` | 通知メールの宛先（`''` なら自分あて） |
| `NOTIFY_WHEN_NOTHING` | 0件の日も通知するか（既定: しない） |
| `DRY_RUN` | `true` にすると保存せずログ出力だけ |
| `IMPORT_DRIVE_FOLDER_IDS` | `importDriveFolders()` の取り込み元フォルダID |

## 仕組みの中でしていること

- **二重保存の防止**: 索引簿のN列「重複防止キー」にGmailのメッセージIDを記録し、
  すでにある分は再保存しません。`backfillAll()` を何度実行しても増えません。
- **受領と発行の判定**: 検索条件ではなく差出人が自分かどうかで判定するため、
  1つのスレッドに受信と送信が混在していても取り違えません。
- **添付がない請求書メール**: メール本文（取引年月日・取引先・金額の見出し付き）をPDF化して保存します。
- **同時実行の防止**: `LockService` で二重起動を防いでいます。

## 注意点・限界

- **金額の自動読み取りは万能ではありません。** 「合計」「Amount paid」などの語の近くの数字を優先し、
  見つからないときは本文中で最大の金額を採用しています。必ず「要確認」欄で目視確認してください。
- **PDFの中身は読んでいません。** 既存フォルダから取り込んだPDFの金額は空欄になります。
- **原本の削除はしません。** Gmailのメールも、既存ドライブフォルダの元ファイルもそのまま残ります
  （`importDriveFolders()` はコピーを作ります）。
- **Google Apps Scriptの1日の実行時間上限は約90分**です。過去分の取り込みで途中終了した場合は、
  もう一度 `backfillAll()` を実行してください。保存済みの分はスキップされます。
- スキャンした**紙の領収書**はこの仕組みの対象外です（電帳法上は「スキャナ保存」という別の区分で、
  紙の原本を残しておけば従来どおりの扱いで問題ありません）。

## iCloud にある請求書について

この仕組みが扱うのは **Gmail と Googleドライブ** の分です。
iCloud Drive の中にある請求書は、Mac 上で動かす別のスクリプトで集めます。
手順は `docs/dencho-icloud-invoice.md` を参照してください。

そちらで集めたファイルは同じ保存フォルダに入るので、
Google Apps Script で **`indexArchiveFolders`** を実行すれば同じ索引簿にまとまります。
（`indexArchiveFolders` は、保存フォルダに手作業で入れたファイルも拾ってくれます。）
