# 院内PC → NAS → クラウド 自動バックアップシステム（3-2-1ルール対応）

院内の各PCのデータを **毎日自動で NAS にバックアップ**し、さらに **NAS の中身を
毎晩クラウドへ二重化**する仕組みの設計と設定手順です。

## 全体像

```
┌─ 院内 ─────────────────────────────────┐
│  受付PC (Windows)  ─┐                          │
│  施術記録PC (Windows) ─┼─ 毎日 20:00 に自動コピー │
│  先生の Mac        ─┘        ↓                 │
│                            NAS                  │
│                    （PCごとのフォルダに保存）      │
└──────────────────┼─────────────┘
                              │ 毎晩 21:30 に自動コピー
                              ↓
                          クラウド
                 （Synology C2 / Backblaze B2 /
                   Google ドライブ など）
```

### 3-2-1ルールをどう満たすか

| ルール | この仕組みでの実現方法 |
|---|---|
| **コピーを3つ** | ① PC本体（原本） ② NAS ③ クラウド |
| **媒体を2種類** | PC/NAS のディスク + クラウドストレージ |
| **1つは別の場所** | クラウド（院内が火災・盗難・水害にあっても残る） |

さらに次の対策も入っています。

- **誤削除対策**: PC 側でファイルを消しても、NAS からは消しません。
  クラウド側も、消えた・上書きされたファイルは「アーカイブ」に90日残ります。
- **ランサムウェア対策**: NAS のスナップショット機能（後述）を有効にすると、
  PC が感染してバックアップまで暗号化されても、感染前の状態に巻き戻せます。
- **失敗に気づける**: 失敗すると PC のデスクトップに「【要確認】バックアップ失敗.txt」
  （Mac は画面右上に通知）が出ます。何も出なければ正常です。

### 既存の仕組みとの関係

すでに動いている「Googleドライブ → iCloud バックアップ（毎日20:15）」はそのまま
併用できます。あちらは Googleドライブ上のデータ、こちらは各PCの中のデータが対象です。

## 準備するもの

### NAS（まだ持っていない場合）

| 項目 | 推奨 |
|---|---|
| 機種 | Synology の2ベイモデル（例: DS224+ / DS223）。国内で情報が多く、クラウド連携（Hyper Backup）が簡単 |
| ディスク | NAS用HDD（WD Red / Seagate IronWolf）を **2台**、RAID1（ミラー）で使う。容量は「全PCのデータ合計 × 3倍」が目安 |
| 設置 | 院内のルーターに有線LAN接続。転倒・水濡れしない場所に |

QNAP でも同等のことができます（クラウド連携は HBS 3 を使用）。

### NAS の初期設定でやっておくこと

1. **バックアップ専用の共有フォルダを作る**（名前の例: `backup`）
2. **バックアップ専用ユーザーを作る**（名前の例: `backup-user`）。
   このユーザーには `backup` フォルダの読み書き権限だけを与える
   （管理者アカウントを各PCに覚えさせないため。ランサムウェア対策としても重要）
3. **スナップショットを有効にする**（Synology: 「Snapshot Replication」パッケージ →
   `backup` フォルダに対して「毎日・14日保持」程度で設定）
4. NAS の IP アドレスを固定する（ルーター側の DHCP 固定割当でもOK）

## ステップ1: 各PC → NAS の毎日バックアップ

対象フォルダは初期設定で「書類（Documents）・デスクトップ・ピクチャ」です。
増やしたい場合は各スクリプト冒頭の「設定」ブロックに追記してください。

### Windows PC の場合（PCごとに1回作業）

1. 各PCで一度、エクスプローラーのアドレス欄に `\\NAS名\backup` と入力して開き、
   バックアップ用ユーザーのIDとパスワードを入力。
   **「資格情報を記憶する」に必ずチェック**を入れる
2. このリポジトリの `scripts/backup/pc-to-nas/windows` フォルダを PC にダウンロード
   （GitHub のページから「Code」→「Download ZIP」でもOK）
3. スタートメニューで「PowerShell」を検索して開き、次を入力して Enter
   （フォルダの場所は読み替え）:

   ```
   cd ダウンロードした場所\scripts\backup\pc-to-nas\windows
   powershell -ExecutionPolicy Bypass -File install.ps1
   ```

4. NAS のパス（例: `\\NAS\backup`）を聞かれるので入力
5. 「✅ セットアップ完了！」と出たら終わり。その場で1回目が実行されます

→ 以後、**毎日 20:00** に自動実行。20:00 に電源が入っていなくても、
次に PC を起動したときに自動で実行されます。

### Mac の場合

1. Finder で「移動」→「サーバへ接続」→ `smb://NAS名/backup` で一度接続し、
   **「このパスワードをキーチェーンに保存」にチェック**を入れてログイン
2. このリポジトリの `scripts/backup/pc-to-nas/mac` フォルダを Mac にダウンロード
3. ターミナルで:

   ```
   cd ダウンロードした場所/scripts/backup/pc-to-nas/mac
   bash install.sh
   ```

4. 接続中の NAS フォルダの一覧が表示されるので、保存先にしたいフォルダの
   **番号を半角数字で入力**して Enter
   （一覧が出ない場合は、アドレスを `smb://192.168.1.10/backup` のような形で
   手入力します。共有フォルダ名まで含めてください）
5. **フルディスクアクセスの許可（1回だけ・必須）**
   Macのプライバシー保護のため、この設定をしないと自動実行時に
   「Operation not permitted」でコピーが失敗します。
   1. アップルメニュー →「システム設定」→「プライバシーとセキュリティ」→「フルディスクアクセス」
   2. 左下の「＋」をクリック（Touch ID かパスワードを求められます）
   3. ファイル選択画面で **Command + Shift + G** を押し、`/bin/bash` と入力して Enter
   4. 「bash」を選んで「開く」→ 一覧に追加された「bash」のスイッチをオンにする

→ 以後、**毎日 20:00** に自動実行（スリープ中だった場合は解除後に実行されます）。

### バックアップされないもの（Mac）

写真アプリの「写真ライブラリ」（`.photoslibrary`）や、iMovie・GarageBand などの
**ライブラリ形式のファイルは対象外**です。これらはアプリが常に中身を読み書きしているため
コピーが必ず途中で失敗し、仮にコピーできてもその方法では正しく復元できません。

写真は次のどちらかで守ってください。

- **iCloud写真をオンにする**（システム設定 → Apple ID → iCloud → 写真）。
  これだけで写真はクラウドに保存され、3-2-1の「別の場所」も満たせます
- または「写真」アプリで大事な写真を選び、「ファイル」→「書き出す」で
  書類フォルダなどに書き出す（書き出したものは翌日のバックアップ対象になります）

### 保存のされかた

NAS の共有フォルダの中に「**PCバックアップ**」フォルダができ、その中に
**PCごとの名前のフォルダ**、さらにその中に Documents / Desktop / Pictures が
そのままの形で入ります。各PCのフォルダ内の `_最終バックアップ日時.txt` を見れば、
いつ成功したかが分かります。

## ステップ2: NAS → クラウドの毎晩バックアップ（二重化）

3つの方法があります。**Synology なら方法A が一番簡単でおすすめ**です。
実行時刻は、PC→NAS のバックアップが終わったあとの **21:30** にします。

### クラウドの選びかた

| サービス | 向いている場合 | 目安費用 |
|---|---|---|
| Synology C2 Storage | Synology NAS を使う場合。設定が最も簡単 | 1TB で月 約500円〜 |
| Backblaze B2 | 容量あたりが安い。rclone / Hyper Backup 両対応 | 1TB で月 約$6 |
| Google ドライブ（Google One） | すでに契約中の容量が余っている場合 | 追加費用なし〜 |

※ 患者情報を含むデータを預けるため、どのサービスでも**バックアップ側の暗号化
（クライアントサイド暗号化）を必ず有効に**します。以下の各手順に含まれています。

### 方法A: Synology「Hyper Backup」（推奨）

1. NAS の管理画面（DSM）→ パッケージセンター → **Hyper Backup** をインストール
2. Hyper Backup を開く → 「＋」→「フォルダとパッケージ」
3. バックアップ先で使うクラウドを選択
   - Synology C2 → 「C2 Storage」（アカウント作成に誘導されます）
   - Backblaze B2 → 「S3 Storage」→ カスタムURLに B2 の S3互換エンドポイント
   - Google ドライブ → 「Google Drive」
4. バックアップ対象に共有フォルダ `backup` を選択
5. スケジュール: **毎日 21:30**
6. **「クライアント側の暗号化を有効にする」にチェック**し、暗号化パスワードを設定
   → このパスワードは紙に書いて院外（自宅など）にも保管。
   **忘れるとクラウドから復元できなくなります**
7. ローテーション設定: 「Smart Recycle」・バージョン数 30 程度
8. 作成後、「今すぐバックアップ」で初回を実行（初回は数時間〜かかることがあります）

失敗時は DSM の通知設定（コントロールパネル → 通知）でメール通知を有効にして
おくと、`kishimoto.karada.condition@gmail.com` に知らせが届きます。

### 方法B: QNAP「HBS 3」

QNAP の場合は App Center から **HBS 3 Hybrid Backup Sync** を入れ、
「バックアップジョブ」で同様に（対象 `backup`、毎日21:30、暗号化オン、
バージョン保持30）を設定します。

### 方法C: rclone（汎用・上級者向け）

Synology/QNAP 以外の NAS や、細かく制御したい場合は
`scripts/backup/nas-to-cloud/rclone_nas_to_cloud.sh` を使います。

1. NAS に SSH でログインし、rclone をインストール（https://rclone.org/install/）
2. `rclone config` でクラウド接続を作成。リモート名は `cloud` にする
   （暗号化するには、さらに crypt リモートを重ねて、それを `cloud` と命名）
3. スクリプトを NAS に置き、冒頭の `SRC`（バックアップフォルダの実パス。
   Synology なら `/volume1/backup`）を確認
4. NAS のタスクスケジューラで **毎日 21:30** に実行するタスクを登録:

   ```
   sh /volume1/backup/.scripts/rclone_nas_to_cloud.sh
   ```

このスクリプトは、クラウド側で消える・上書きされるファイルを日付つきの
アーカイブフォルダに90日間残します（誤削除・ランサムウェア対策）。
失敗すると NAS の `backup` フォルダ直下に「【要確認】クラウドバックアップ失敗.txt」
が作られるので、PCからも気づけます。

## 動作確認と日々の運用

### 設定直後に確認すること

- [ ] 各PCの1回目のバックアップが成功した（NAS にPC名のフォルダができている）
- [ ] NAS→クラウドの初回バックアップが完了した
- [ ] クラウド側の管理画面でファイル（またはバックアップジョブ）が見える
- [ ] わざとテスト用ファイルを1つ復元してみて、開けることを確認した

### ふだんの運用（ほぼ何もしなくてOK）

- 失敗するとデスクトップの通知ファイル / Mac通知 / メールで知らせが来ます。
  **何も出ていなければ正常**です
- 20:00〜22:00 ごろは PC と NAS の電源を入れたままにしておくと確実です
  （切れていても次回起動時に自動で追いつきます）

### 月1回のチェック（5分）

- [ ] NAS の各PCフォルダの `_最終バックアップ日時.txt` が最近の日付になっている
- [ ] Hyper Backup（またはrcloneログ）の最終成功日時が昨日以降になっている
- [ ] どれか1ファイルを選んで、クラウドから実際に復元して開けるか試す
- [ ] NAS のディスクとクラウドの空き容量に余裕があるか見る

### 復元のしかた

| 失ったもの | 復元元 | 方法 |
|---|---|---|
| ファイルを誤削除・上書き | NAS | エクスプローラー/Finder で `\\NAS\backup\PC名\...` を開いてコピーで戻す |
| NAS上でも壊れていた | NASスナップショット | DSM →「Snapshot Replication」→ 復元したい日時を選ぶ |
| PCが故障・買い替え | NAS | 新PCで同じフォルダをコピーで戻し、install を再実行 |
| 院内ごと被災・NAS故障 | クラウド | Hyper Backup の「復元」（暗号化パスワードが必要）/ rclone なら `rclone copy cloud:kishimoto-nas-backup 復元先` |

## よくある質問

**Q. バックアップの時刻を変えたい**
Windows: 「タスク スケジューラ」で `kishimoto-backup-to-nas` のトリガーを編集。
Mac: `install.sh` の `RUN_HOUR` / `RUN_MINUTE` を変えて再実行。
NAS→クラウド: Hyper Backup またはタスクスケジューラの設定画面で変更。

**Q. バックアップ対象のフォルダを増やしたい**
各スクリプト冒頭の「設定」ブロック（`$Targets` / `TARGETS`）にフォルダを追記して、
もう一度 install を実行してください。

**Q. 自動バックアップをやめたい**
Windows: PowerShell で
`Unregister-ScheduledTask -TaskName kishimoto-backup-to-nas -Confirm:$false`
Mac:
```
launchctl bootout gui/$(id -u) ~/Library/LaunchAgents/com.kishimoto.nas-backup.plist
rm ~/Library/LaunchAgents/com.kishimoto.nas-backup.plist
```

**Q. PCで消したファイルがNASに残り続けて容量が心配**
誤削除対策のためわざと残しています。年に1回程度、NAS のPC名フォルダの中で
明らかに不要なものを手動で削除すればOKです（削除してもクラウドのアーカイブに
90日残ります）。

**Q. 患者情報を扱っているが安全か**
院外に出るのは「NAS→クラウド」の部分だけで、そこは暗号化（Hyper Backup の
クライアント側暗号化、または rclone crypt）をかける手順にしています。
暗号化パスワードの紙保管だけ忘れずに。院内側も、NASのバックアップ用ユーザーを
専用にして権限を絞ることで、PCが乗っ取られてもNAS全体には触れないようにしています。
